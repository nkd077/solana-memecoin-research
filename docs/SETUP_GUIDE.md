## Куда физически идут твои 3 SOL

Это НЕ депозит на биржу и не перевод мне или куда-то ещё. Схема такая:

1. Ты создаёшь (или используешь) отдельный Solana-кошелёк в Phantom/Solflare — не основной, специально для бота.
2. Отправляешь на его публичный адрес 3 SOL с любой биржи (Binance, OKX и т.д.) или из другого кошелька — обычный перевод в сети Solana.
3. Экспортируешь ПРИВАТНЫЙ ключ этого кошелька (в Phantom: Настройки → показать приватный ключ) и вписываешь в `.env` как `PRIVATE_KEY`.
4. Приватный ключ живёт ТОЛЬКО в `.env` на твоём компьютере — никуда не отправляется, кроме как локально используется, чтобы подписывать транзакции.
5. Когда бот решает купить: он строит своп-транзакцию (SOL → токен) через Jupiter, подписывает её ЛОКАЛЬНО твоим ключом, отправляет через Jito прямо в блокчейн Solana. Токен оказывается на том же кошельке.
6. Когда продаёт — то же самое в обратную сторону (токен → SOL), тоже локально подписанная транзакция.

**Деньги не покидают твой кошелёк, пока сам кошелёк не подпишет транзакцию** — это не custodial-сервис, где кто-то держит твои деньги. Но именно поэтому приватный ключ — это единственная точка риска: если файл `.env` попадёт не в те руки, кошелёк можно опустошить. Держи `.env` только на своей машине, никогда не отправляй его никому (в том числе мне) и не коммить в git.

⚠️ **НИКОГДА** не коммитьте `.env` с реальным приватным ключом в git!

**Цель**: Собрать статистику, понять, какие кошельки реально выигрывают, накопить данные.

### 2.1. Запустить бота
```bash

```

Будет спам логов. Открой второй терминал:

### 2.2. Смотреть основные события
```bash
# В отдельном терминале:
tail -f logs/sniper_bot.log | grep -E "НОВЫЙ ТОКЕН|Кит|подтверждён|успешно"
```

Ожидаемые строки:
- `НОВЫЙ ТОКЕН ... от ... цена $...` — бот видит ранних покупателей
- `Кит ... продаёт ...` — бот видит продажи китов
- `подтверждён как смарт-мани` — кошелёк получил флаг (это редко, как минимум 20 сделок)

### 2.3. Проверять статистику раз в день
```bash
python -m research.stats_report --days 1
```

Смотреть:
- **Win rate** — должен быть >50%, идеально >60%
- **Средний P&L** — если отрицательный, пороги слишком низкие
- **Причины выхода** — большинство по whale-mirror, а не по stop-loss?
- **Топ кошельки** — есть ли 1–2 кошелька, что постоянно выигрывают?

### 2.4. Сигналы проблем (не включай реальные деньги!)
Если видишь за неделю:
- ❌ Win rate <40%
- ❌ Максимальная просадка >30%
- ❌ Каждая вторая сделка на honeypot/скам-монету
- ❌ Один кошелёк копируется на каждую монету (залипание в цикле)

→ **Жди ещё неделю, не включай DRY_RUN=false**

Хорошие знаки:
- ✅ Win rate стабилен >55%
- ✅ Есть 2–5 кошельков с winrate >65%
- ✅ Средний P&L на сделку >0.05 SOL (в бумажном режиме)
- ✅ Максимальная просадка <20%

**Минимум неделя в этом режиме перед включением реальных денег.**

## ЭТАП 5: Платформы для торговли

Бот использует:

| Компонент | Назначение |
|---|---|
| **Raydium AMM v4** | DEX на Solana, где торгуются Pump.fun токены. Ликвидность, свопы. |
| **Jupiter** | Агрегатор маршрутов (находит лучший путь для swap). |
| **Jito** | MEV-protection (приоритет транзакций, защита от фронтрана). |
| **Helius RPC** | Данные блокчейна (покупки/продажи, цены, ликвидность). |

**Нет других бирж.** Если хочешь торговать на Robinhood — это совсем другой бот (не для Solana мемкойнов).

### Почему именно эти?

- Raydium + Jupiter = лучшая ликвидность для новых Pump.fun токенов
- Jito = защита от MEV (фронтран, sandwiching) — без этого потеряешь 5–10% на иксах
- Helius = самый быстрый RPC для отслеживания новых токенов

## ЭТАП 6: Техническая поддержка / Отладка

### Если бот не видит новые токены
```bash
# Проверь Helius API:
curl -X POST https://api.helius.xyz/v0/parsed-transactions \
  -H "Content-Type: application/json" \
  -d '{"api-key":"YOUR_KEY","transactions":["..."]}' | jq .

# Если 401 — ключ неправильный
# Если 429 — лимит квот, жди
```

### Если продажи не работают
```bash
# Проверь солдо токена в кошельке (через Phantom или Solscan):
https://solscan.io/account/<WALLET_ADDRESS>?cluster=mainnet-beta

# Если токена нет — бот его не купил (проверь логи)
```

### Если бот зависает
```bash
# Обычно Redis проблема:
brew services stop redis
brew services start redis

# Или просто перезапусти с чистым DRY_RUN=true
```

## ⚠️ ФИНАЛЬНЫЕ ПРЕДУПРЕЖДЕНИЯ

### На реальных деньгах:
1. **Потери случаются.** Даже с win rate 60%, половина сделок проигрышные.
2. **Максимум потеряешь 3 SOL**, если всё пойдёт плохо. Не вкладывай больше.
3. **Не менять пороги на лету.** Если что-то пошло не так — вернись в DRY_RUN, не меняй конфиг в панике.
4. **Не доверяй одному киту.** Копировать нужно минимум 3–5 разных кошельков с доказанным win rate.
5. **Мониторь каждый день.** Рынок крипто меняется быстро; кошельки, что были прибыльны, могут стать убыточны.

### Если потеряешь 50% или больше:
- **Не паникуй.**
- Выключи реальную торговлю.
- Жди месяц, собирай данные в DRY_RUN.
- Калибруй модель заново.
