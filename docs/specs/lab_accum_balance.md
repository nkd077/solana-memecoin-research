Журнал: [`CLOSED_HYPOTHESES.md`](../CLOSED_HYPOTHESES.md) §A10–A11, C1.

Пилот 2026-09-08→09: архив `data/pilot_lab_accum_balance_2026-09-09/`

**активность**. Здесь мерим **состояние** — рост концентрации топ-держателей
при неподвижной/падающей цене.

## 1. H1 — главная гипотеза

Honest медианная доходность за **7 дней** от момента сигнала **≥ 0**, при
строгом `is_exit_tradeable` на выходе.

**Популяция:** токены из `graduates_cohort` с пулом ≥ **100 × размера позиции**
на момент сигнала (`ACCUM_BAL_POSITION_SOL`, default 0.05 SOL), принятые в
`active-set` случайным admission.

Горизонт **7 дней**, не 24 часа: накопление медленное; суточное окно — шум.

### H2 (собираем — отличие от vol_spike)

`honest med(накопление) > honest med(контроль)`.

Контроль: каждое полное не-void окно active-set → запись с `is_signal` true/false.

**Провал H1 закрывает ветку независимо от H2.**

### H3 (отдельно, не смешивать с H1)

Предсказывает ли накопление **выживание** токена (пул ≥ порога через 7 дней).

## 2. Определение сигнала

**Снимок каждые 6 часов** (`ACCUM_BAL_SNAP_SEC=21600`):

- `getTokenLargestAccounts` → топ-20 + балансы (1 RPC / mint)
- цена и ликвидность DexScreener (пачки по 30): **max liq только внутри
  одного ответа**; отсутствие mint в pairs → `dex_missing` (не старый кэш);
  HTTP/сеть → retry

**Из топ-20 исключаются:**

- аккаунт пула AMM (резолв один раз: owner PDA принадлежит программе AMM;
  через `getMultipleAccounts` как в `rug_checker` — **не** ATA-формула)
- держатель с долей **> 50%** от кэшированного supply
- известные burn-адреса

**conc(t)** = сумма **абсолютных** балансов оставшихся держателей (не доля).

```
d_conc_pct = (conc_now − conc_prev) / conc_prev
d_conc_usd = (conc_now − conc_prev) × price_now
base_usd   = conc_prev × price_prev
```

Supply (`getTokenSupply`) — **один раз** при входе mint: только для правила >50%
и отчёта.

**Окно = 4 снимка (~24 часа).** Сигнал, если одновременно:

| # | Условие |
|---|---------|
| 1 | `d_conc_pct ≥ +5%` |
| 1b | `d_conc_usd ≥ base_usd × 0.05` — абсолютный пол от **базы**, не от позиции |
| 2 | монотонность: шаг окна не падает больше чем на 1% |
| 3 | `Δцены ∈ [−30%, +10%]` |
| 4 | liq ≥ порога популяции на всех снимках |

В каждое окно пишем `window_hours = (ts_last − ts_first) / 3600`.
Если `window_hours > 36` → void `window_too_long`.

**Снимок хранит `top_accounts` как `[[addr, uiAmount], ...]`** (порядок топа)
и `top_floor` = min баланс в списке (порог 20-го места). Рядом —
`top_retention = |prev ∩ now| / |prev|`.

В **jsonl** — полные пары; в **meta.snaps** — только адреса (без балансов).

Разложение Δconc между кадрами (и first→last окна):

```
d_persist = Σ (b_now − b_prev)  по адресам в обоих
d_in      = Σ b_now             по вошедшим
d_out     = Σ b_prev            по выбывшим
persist_share = |d_persist| / (|d_persist| + |d_in| + |d_out|)
```

В окно пишутся `persist_share`, `d_persist`, `d_in`, `d_out`,
`top_retention_min` / `top_retention_mean`. **Пороги сигнала от этого не зависят** —
только диагностика (a) vs (b).

### Диагностика (a)/(b) — зафиксировано до данных (2026-09-10)

По первым **40** не-void окнам с `base_usd ≥ $150`:

| Вердикт | Условие |
|---------|---------|
| **(a)** эффект отсутствует в когорте | med `persist_share` ≥ 0.50 **и** med `top_retention_min` ≥ 0.80 |
| **(b)** прибор меряет текучку слотов | med `persist_share` ≤ 0.30 **или** med `top_retention_min` < 0.65 |
| неопределённо | иначе → продлить до 80 окон |

Если `persist_share` и `top_retention` **расходятся** — решающий **`persist_share`**
(вопрос про деньги; retention шумит на dust-адресах у дна списка без массы).
Числа — пререгистрация суждения, не вывод из данных.

### Обрезка топа — по `top_floor_usd`, не по `holders_count`

`holders_count == 19` **не** означает обрезку глубокого распределения: RPC часто
возвращает ≤20 аккаунтов и добивает список пылью (`top_floor_usd ≪ $0.01`).

Признак «обрезка / уровень отсечки значим»:

`top_floor_usd = top_floor × price ≥ $1` (пререгистрация; пыль пилота ≪ $0.01).

Сравнивать Δconc / сигналы между подгруппами `top_floor_usd ≥ $1` vs `< $1`.
Токены различаются и иначе — наблюдение, не чистый эксперимент. Если
накопление видно только при низком floor (полный хвост), а при высоком floor
нет — довод в пользу (b) **в подгруппе с реальной отсечкой**; правило (a)/(b)
тогда считать по окнам с `top_floor_usd ≥ $1`.

**Void дополнительно:** `base_usd < MIN_CONC_USD` (**$150**, ≈p25 пилота) —
база слишком мала; иначе Δ% взрывается на пыли у порога.

Примечание v2: условие `d_conc_usd ≥ base×0.05` алгебраически почти совпадает с
`d_conc ≥ 0.05` (отличается лишь через `d_price`); отдельным фильтром почти не
является. Оставлен для аудита; реальный пол — `MIN_CONC_USD`.

**Кулдаун сигнала:** 48ч / mint. Контрольные окна пишутся всегда.

**Покрытие:** случайный `active-set` фиксированной ёмкости (~530). Round-robin
только по active. Admission в свободные слоты случайный (`admitted_ts` /
`admit_reason`).

**Нейтральное выбывание:**

- `liq_below_threshold_twice`
- `max_completed_windows` (K окон, независимо от сигнала)
- `no_window_after_n_snaps`

Mint с незавершённым окном не выбывает.

В статистику **ничего**, пока нет полного окна из 4 точек.
