# Снайпинг-бот для мемкоинов на Solana (Whale Copy Trading)

> **Обновление по реализации:** изначальный план — брать список "китов"
> у GMGN.ai — не сработал напрямую: GMGN отдаёт сделки только по уже
> известному списку адресов, а не общий поток по всей сети. Вместо этого
> бот строит список инсайдеров сам, наблюдая за ранними покупателями новых
> токенов на Pump.fun и отслеживая, чьи покупки потом "выстреливают" (см.
> README.md, раздел "Как бот находит инсайдеров сам"). Раздел ниже — это
> исходная концепция как она была задумана изначально.

## Общая концепция

Автоматизированная торговая система для снайпинга (мгновенной покупки)
мемкоинов на блокчейне Solana. Стратегия основана на копировании сделок
крипто-китов (инсайдеров) — крупных игроков, которые часто имеют
информацию о предстоящих листингах на крупных биржах (например,
Robinhood) и совершают покупки до официального объявления.

## Техническая архитектура

### 1. Источники данных (обнаружение сигналов)

| Источник | Назначение | Доступ |
|---|---|---|
| Arkham Intelligence | Идентификация китов, метки кошельков, история транзакций | Платный API |
| GMGN.ai | Поток сделок "умных денег" в реальном времени, WebSocket | Бесплатный/платный API |
| Birdeye / DexScreener | Цены, ликвидность пулов, безопасность токенов | Бесплатный API |
| Helius RPC | Прямое чтение блокчейна Solana | Бесплатный (25k/день) |

### 2. Ключевые компоненты

**А. Парсер транзакций** — анализирует блокчейн Solana в реальном
времени, распознаёт покупки через Raydium AMM v4 и Pump.fun, извлекает
сумму в SOL, адрес токена, пул ликвидности.

**Б. Скоринг-движок (ML-модель)** — оценивает вероятность успеха каждой
сделки кита:

| Признак | Вес | Описание |
|---|---|---|
| Свежесть кошелька | 15% | Крупный перевод на кошелёк перед покупкой |
| Низкая ликвидность | 15% | Пул < $50 000 (быстрый рост цены) |
| Влияние на цену | 12.5% | Покупка > 5–15% от ликвидности пула |
| Кластер покупок | 22.5% | 2+ китов купили токен за 30 минут |
| Smart Money флаг | 10% | Метка от GMGN (проверенный кит) |
| Исторический winrate | 12.5% | % успешных сделок кита в прошлом |
| Метка Arkham | 12.5% | Кошелёк размечен как whale/insider |

Итоговый скор: от 0 до 1, порог срабатывания по умолчанию > 0.65.

**В. Бэктест-фреймворк** — собирает исторические данные по кошелькам
китов, размечает события (успех/провал через 48 часов), обучает
логистическую регрессию с TimeSeriesSplit, калибрует веса признаков,
предотвращает утечку данных (data leakage).

**Г. Исполнительный модуль (Jito + Jupiter)** — запрос котировки через
Jupiter (лучший маршрут свопа), сборка транзакции с учётом
проскальзывания, подпись приватным ключом, отправка через Jito Block
Engine (приоритизация) с tip-транзакцией для ускорения.

**Д. Управление рисками**:

- Максимальный размер позиции: 0.01–0.5 SOL
- Не более 5 одновременно открытых позиций
- Не более 1 позиции на одного кита
- Дневной стоп-лосс: 10% просадки
- Не более 2% от ликвидности пула (чтобы не двигать цену)

### 3. Технический стек

- Язык: Python 3.9+
- Фреймворки: asyncio, aiohttp, websockets
- Блокчейн: solana, solders
- ML/Аналитика: pandas, scikit-learn (логистическая регрессия)
- Кэширование: Redis
- Инфраструктура: Helius RPC, Jito Block Engine

### 4. Этапы разработки

1. **Бэктест и калибровка** — сбор исторических данных (30+ дней),
   обучение ML-модели, калибровка весов, валидация на вневыборочных данных.
2. **Тестирование (DRY_RUN)** — подключение к реальным API, мониторинг
   китов без отправки транзакций, сравнение предсказаний с реальными
   движениями цены, настройка порогов и лимитов.
3. **Продакшен (минимальными суммами)** — реальные транзакции от 0.01
   SOL, мониторинг исполнения и проскальзывания, постепенное увеличение
   позиций, автоматический stop-loss.

### 5. Риски и ограничения

⚠️ Высокорискованная стратегия:

- Мемкоины — большинство заканчиваются rug-pull или быстрым сливом
- Киты могут ошибаться или быть приманкой
- Задержки — даже 0.5 секунды могут стоить прибыли
- Проскальзывание при низкой ликвидности
- Jito-комиссии съедают прибыль при малых сделках
- Возможны регуляторные риски
